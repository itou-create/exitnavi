# 出口ナビ

駅の出口案内アプリ。**どの路線のどのホームから来たか**を特定して、目的地に対して最適な出口を出します。

公共交通オープンデータチャレンジ2026 応募検討用のプロトタイプです。

---

## なぜ「何線で来たか」が要るのか

出口案内の中身は経路探索です。GTFS-Pathways で経路を引くには `from_stop_id` が要りますが、これは**駅IDではなくホームのID**です。

池袋駅は4事業者8路線、ホームは地上1Fから地下4Fまで散らばっています。同じ「サンシャイン水族館」でも、JR埼京線から来たか副都心線から来たかで最適な出口が変わります。

**駅を特定しただけでは案内が始まりません。**

## どう解いているか

ODPT の**リアルタイム走行位置API**と、アプリの起動時刻を突き合わせます。

```
起動時刻 12:04:12
  → 直近90秒に池袋へ到着した列車を走行位置APIから取得
  → すでに発車済みの列車を除外
  → 「12:03:41着、JR埼京線 大宮方面ですね？」と当てにいく
  → 違えば8路線から1タップで選び直し
```

当たれば操作ゼロ、外れても損がない。だから推定を先に出せます。

走行位置APIを「遅延表示」ではなく**「ユーザーの現在地推定」**に使うのが、この実装の要点です。列車の位置から人の位置を逆算しています。

## 動かす

```bash
npm install
npm run dev
```

**APIキーは無くても動きます。**`VITE_ODPT_TOKEN` が未設定なら自動でモックデータにフォールバックし、画面上に「モックデータ」と表示されます。

実APIに繋ぐ場合：

```bash
cp .env.example .env.local
# .env.local に https://developer.odpt.org/ で取得したトークンを書く
```

深夜など列車が走っていない時間帯に開発する場合は `VITE_FORCE_MOCK=true` にしてください。

```bash
npm run build     # 型チェック + ビルド
npm run preview   # ビルド結果を確認
```

`dist/` が静的ファイルなので、GitHub Pages にそのまま置けます。サブディレクトリに置く場合は `vite.config.ts` の `base` を調整してください。

## いまの制約

**`src/data/stations.ts` の数値はすべて暫定値です。**出口の座標、ホームから改札までの所要時間、階段の段数——現地で確認していません。`// TODO: 実測` を付けてあります。

本来これらは GTFS-Pathways の `pathways.txt` から経路探索して求める値ですが、日本の駅ではこの規格がほぼ未整備です。整備されるまでの繋ぎとして、ホーム→出口のコストを直接テーブルで持たせています。

対応駅は**池袋・仙台・六丁の目（仙台市地下鉄東西線）・船橋**です。

**仙台圏では起点の自動推定はできません。**ODPT のカタログで確認した結果（2026-08）、仙台市交通局が提供しているのはバスの GTFS のみで地下鉄の走行位置は無く、JR東日本の走行位置も首都圏在来線のみでした。仙台の2駅では手動選択が正規ルートになり、その旨を画面にも表示します（モック時のみ推定デモが動きます）。

対応駅から離れた場所で開いた場合は、駅の自動判定をせず「どの駅にいますか？」画面で選ばせます。デモモード（モックデータで池袋着の想定）もそこから選べます。

## 実測で精度が上がる仕組み（クラウドソーシング）

アプリ自体が計測器になっている。案内どおりに歩くと、ステップごとの
所要秒数・歩数・回転角が自動記録され（位置の履歴は記録しない）:

1. **端末内学習** — 同じ経路を2回以上歩くと、その端末ではデータの無いステップでも
   「実測目安◯歩」で自動判定が効くようになる。距離既知の区間を歩くと
   **歩幅も自動キャリブレーション**され、距離推定が個人に合っていく
2. **提供** — 案内完了時の「計測データを提供する」で共有シートから送れる
   （送信は本人操作のみ）
3. **コミュニティ集約** — 提供された記録の中央値を `src/data/measured.ts` に
   集約してデプロイすると、**全員のアプリ**で自動判定・所要時間が正確になる

新しい駅は「公開情報の暫定値で公開 → 利用者の歩行記録で精緻化」の流れで育てる。

## データ収集の3層戦略

追加した駅を1駅ずつ人が実地検証するのはスケールしないため、収集を3層に分ける:

1. **自動収集（オープンデータ）** — [歩行空間ネットワークデータ](https://www.geospatial.jp/ckan/dataset/0401)が
   整備されている駅（**池袋駅周辺は公開済み**。東京駅・新宿駅周辺、都営大江戸線12駅構内も）は、
   階段・改札・通路のネットワークから方向・距離を機械的に算出する（インポーター未実装・次の開発項目）。
   出口座標は OSM から自動取得済み
2. **アプリ内フィードバック** — 案内画面の「実際と違っていたら報告する」ボタンから、
   その場で GitHub Issue が立つ（表示されていた案内とデータの対象箇所が自動で入る）
3. **実地調査シート** — 未整備駅用。`docs/survey-sheet.md` に沿えば誰でも1駅15分で
   必要データを収集できる（全項目が `stations.ts` のフィールドに対応）

## 次にやること

1. **歩行空間ネットワークデータ（池袋）のインポーター**を作り、池袋の構内経路・方向・距離を自動生成する
2. **池袋4事業者の走行位置API提供状況を実測する**
   JR東・西武・東武・東京メトロのうち、どこが `odpt:Train` を出しているか。ここで起点推定の成否が決まります
3. `stations.ts` の暫定値を実測に置き換える（`docs/survey-sheet.md` を使用）

## ステップ案内（第2段階・実装済み）

**目標は「案内表示を見なくても目的の出口にたどり着ける」ことです。**

出口の算出結果から「案内を始める」と、改札から出口まで**1画面1指示**で案内します。
各ステップでは方向（大きな矢印。直前の動作を終えた向きが基準）と距離をアプリが言い切り、
案内板の表記は「確認用（答え合わせ）」として添えるだけにしています。
方向データが未整備の経路では、嘘の方向を言い切らず「ここは案内板が頼り」と明示して
フォールバックします。

- **現在地は測りません。**進行はユーザーの「次へ」タップ。屋内で数m粒度の測位はできない、という前提を崩していません
- 最終ステップでのみ「地上に出たか」を測位精度（accuracy）の改善で確認できます（任意・数値ごと表示）
- 案内は**降車直後**（ホームのどっち寄りの階段か）から始まります。ホームの模式図（降りた電車・階段の位置・両端の方面）と、駅の俯瞰模式図（全出口・目指す出口・目的地の方角、北が上）を表示します。**現在位置は描きません**（測っていないため）。未実測の設備位置は「未実測」と明記します
- ステップは `legs[].steps` の手書きデータがあればそれを、無ければ改札名・階段数・案内板表記から自動生成します。将来 GTFS-Pathways の `pathways.txt` を経路探索した結果に置き換わる想定の器です
- 地上に出た後は Google マップの徒歩経路に引き継ぎます（地上ナビは第3段階）

## 目的地のフリーワード検索（任意）

Google Places API (New) のキーを設定すると、目的地画面にフリーワード検索が出ます。
未設定なら検索欄が出ないだけで、プリセットの目的地で全画面が動きます。

1. Google Cloud でプロジェクトを作り、**Places API (New)** を有効化（要課金登録。無料枠あり）
2. APIキーを発行し、**必ず制限をかける**：
   - アプリケーションの制限: HTTPリファラ（`https://<user>.github.io/*` と `http://localhost:5173/*`）
   - APIの制限: Places API (New) のみ
3. ローカルは `.env.local` の `VITE_GOOGLE_PLACES_KEY`、本番は GitHub リポジトリの
   Settings → Secrets and variables → Actions に `VITE_GOOGLE_PLACES_KEY` を登録

⚠️ キーは公開サイトのJSに埋め込まれるため、上記の制限が唯一の保護です。制限なしのキーを絶対に使わないこと。

## 使っているデータ

- [公共交通オープンデータセンター（ODPT）](https://www.odpt.org/) — 列車走行位置
- [OpenStreetMap](https://www.openstreetmap.org/) — 駅出入口の座標（© OpenStreetMap contributors, [ODbL](https://opendatacommons.org/licenses/odbl/)。2026-08 に Overpass API で取得）
- [地理院タイル（淡色地図）](https://maps.gsi.go.jp/development/ichiran.html) — 駅周辺の実地図の背景（出典: 国土地理院）
- 公式の構内図は各事業者の著作物のため埋め込まず、**リンクで開く**（`stations.ts` の `officialMaps`）。アプリ内に埋め込む構内図は、公式図の事実情報（改札・出口・階の構成）を基にした**独自の描き起こし**（`src/ui/floorplans.ts`。現状は六丁の目のみ）
- Google Places API (New) — 目的地検索（任意・キー設定時のみ）
